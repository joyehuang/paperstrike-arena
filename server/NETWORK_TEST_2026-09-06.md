# 前端托管与国内可达性测试

测试日期：2026-09-06。目的是判断迁移前端是否有助于国内朋友关闭代理，避免把前端加载耗时与对局 RTT 混为一谈。此次没有创建或实测 Fly.io 实例，因此结果不能作为 Fly.io 东京/新加坡的线路评价。

## 测试对象

- Vercel 正式入口：https://joyehuang.app/pvp
- 现有 Vultr 东京静态镜像：https://play.joyehuang.app/pvp
- 两者共用游戏后端：https://pvp.joyehuang.app
- 镜像构建版本：4259798fe69a13778d1e7e8fc645dd318a7d271d。

## 本地测试线路

| 项目 | Vercel | Vultr 镜像 |
| --- | ---: | ---: |
| HTML TTFB，5 次中位数 | 31 ms | 248 ms |
| 初始 JS/CSS 成功数 | 18/18 | 18/18 |
| JS/CSS 解压后字节数 | 1,452,155 | 1,452,155 |
| 资源并发下载加音效 HEAD 检查 | 467 ms | 1,851 ms |

上述是 Node fetch 测试，包含连接复用，不是完整浏览器加载指标，也不能外推为国内访问情况。镜像浏览器实际建房成功，验收房间已离开。另以镜像 Origin 完成真实 WSS 双客户端验收，RTT 中位数 234 ms、p95 236 ms，正常快照约 15 Hz。未进行并发负载或实际游戏帧率测试。

## 国内公共探测

通过 [ITDOG HTTP 测试](https://www.itdog.cn/http/) 页面实际提交各目标，选择电信、联通、移动，取消港澳台/海外，运营商 DNS，默认 HTTP/2 向下兼容。各轮完成 252 个节点。以下不是该页面打开时展示的示例数据。

| 目标 | HTTP 200 | 失败 | 成功节点平均总耗时 |
| --- | ---: | ---: | ---: |
| Vercel /pvp | 247 | 5 | 0.874 s |
| Vultr 镜像 /pvp | 0 | 252 | 无成功样本 |
| Vultr 后端 /health | 0 | 252 | 无成功样本 |

东京两域名的探测结果均解析到 45.32.255.230，多数失败显示约 10 秒超时。单一公共探测平台的一轮结果不足以确认失败原因；不能据此直接认定 IP 被封、服务器配置错误或所有国内用户都无法访问。Vercel 返回 HTML 200 也不证明所有游戏资源和 WebSocket 都能正常连接。

随后通过 [ITDOG TCP 测试](https://www.itdog.cn/tcping/) 对 `45.32.255.230:443` 发起三网单次探测，252/252 节点超时，进度 100%。这说明该探测平台遇到的问题不只出现在新域名的网页层；仍需交叉核查云防火墙来源限制、服务器防火墙及真实玩家路由，不能单凭这一项确定根因。

当前证据不支持把正式前端迁到现有 Vultr 来改善国内访问。保留正式入口，镜像仅用于对照；下一步应使用朋友实际宽带关闭代理测试页面与游戏连接，并在实际候选服务器上验证线路后再迁移。购买更大 CPU/内存无法由这些结果推导为有效的延迟解决方案。
